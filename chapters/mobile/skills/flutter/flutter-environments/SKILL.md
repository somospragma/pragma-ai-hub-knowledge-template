# Flutter Flavors & Build Environments

Defines the rules and best practices for implementing different build environment
configurations in Flutter applications.

---

## Design Principles

- **One entry point per flavor.** `main_dev.dart`, `main_staging.dart`, and `main_prod.dart` are the only place where configuration, logging sinks, and Firebase are initialized. No scattered `if (kDebugMode)` in business code.
- **Secrets never travel in the repo.** API keys live in `.env` files ignored by git. `envied` reads them at compile time and embeds them in the binary with `obfuscate: true` — not in the repo, not as plain text in the APK/IPA.
- **Configuration is a typed object, not a Map of Strings.** `AppConfig` is a strongly-typed class accessible from any layer. Eliminates magic strings and scattered `String.fromEnvironment` calls.
- **iOS and Android are parallel.** Every decision made on Android (productFlavor, google-services.json per folder) has its exact equivalent on iOS (scheme, xcconfig, GoogleService-Info.plist per folder). This skill always covers both platforms.
- **CI/CD injects secrets — they are never committed.** GitHub Actions, Azure DevOps, and Fastlane receive secrets as pipeline environment variables and generate the `.env` files at build time. The repo only contains `.env.example` as documentation.

## Project File Structure

```
├── .env.dev                          ← Gitignored — generated in CI or locally
├── .env.staging                      ← Gitignored
├── .env.prod                         ← Gitignored
├── .env.example                      ← Committed — documents required keys
│
├── lib/
│   ├── main_dev.dart                 ← Dev entry point
│   ├── main_staging.dart             ← Staging entry point
│   ├── main_prod.dart                ← Prod entry point
│   └── core/
│       └── config/
│           └── env/
│               ├── app_config.dart       ← Typed configuration object per flavor
│               ├── app_flavor.dart       ← Enum AppFlavor { dev, staging, prod }
│               ├── env_dev.dart          ← Generated by envied from .env.dev
│               ├── env_staging.dart      ← Generated by envied from .env.staging
│               └── env_prod.dart         ← Generated by envied from .env.prod
│
├── android/
│   ├── app/
│   │   ├── src/dev/google-services.json
│   │   ├── src/staging/google-services.json
│   │   ├── src/prod/google-services.json
│   │   └── build.gradle              ← productFlavors + signingConfigs
│   └── key.properties                ← Gitignored — keystore passwords
│
└── ios/
    ├── Runner/
    │   ├── GoogleService-Info-Dev.plist
    │   ├── GoogleService-Info-Staging.plist
    │   └── GoogleService-Info-Prod.plist
    ├── Flutter/
    │   ├── Dev.xcconfig
    │   ├── Staging.xcconfig
    │   └── Prod.xcconfig
    └── Runner.xcodeproj/
        └── xcshareddata/xcschemes/   ← Dev.xcscheme, Staging.xcscheme, Prod.xcscheme
```

## Run Commands per Flavor

```bash
# Development
flutter run --flavor dev -t lib/main_dev.dart

# Staging
flutter run --flavor staging -t lib/main_staging.dart

# Production
flutter build apk --flavor prod -t lib/main_prod.dart
flutter build ipa --flavor prod -t lib/main_prod.dart
```

## Pre-delivery Checklist

- [ ] `.env.*` is in `.gitignore` — never committed
- [ ] `.env.example` documents all keys with placeholder values
- [ ] `envied` uses `obfuscate: true` on all `@Envied` classes — no exceptions
- [ ] `*.g.dart` files generated by envied are in `.gitignore`
- [ ] `AppConfig` is the only place that accesses `EnvDev/Staging/Prod` — nothing imports them directly outside `app_config.dart`
- [ ] Android has `google-services.json` in `src/dev/`, `src/staging/`, `src/prod/`
- [ ] iOS has one `GoogleService-Info.plist` per scheme and a Run Script that copies the correct one
- [ ] Each flavor has its own `applicationId`/`bundleId` — allows installing all 3 simultaneously
- [ ] Keystores and `.p12` files are never in the repo — they live in CI secrets or a vault
- [ ] Use absolute imports with `package:` — never relative imports (`import '../..'`)
- [ ] CI generates the `.env` files from secrets before running `flutter build`
