# Folder Structure — Single Project and Monorepo

Two supported strategies. Choose **one** based on team size and number of apps.

---

## Strategy 1 — Single Project

For small teams or standalone apps. Features live directly under `lib/`.

```
project/
├── android/
├── ios/
├── lib/
│   ├── main.dart
│   ├── core/                                   # Shared code across features
│   │   ├── di/
│   │   │   ├── injection.dart                  # GetIt entry point
│   │   │   ├── injection.config.dart           # Generated by Injectable
│   │   │   └── modules/
│   │   │       ├── network_module.dart
│   │   │       └── storage_module.dart
│   │   ├── error/
│   │   │   └── failure.dart                    # @freezed sealed Failure type
│   │   ├── network/
│   │   │   ├── api_client.dart
│   │   │   └── interceptors/
│   │   ├── storage/
│   │   │   └── cache_store.dart                # Abstract interface
│   │   ├── usecase/
│   │   │   └── usecase.dart                    # UseCase<T,P>, UseCaseNoParams<T>
│   │   └── router/
│   │       └── app_router.dart                 # GoRouter configuration
│   │
│   ├── {feature_a}/
│   │   ├── data/
│   │   │   ├── data_sources/
│   │   │   │   ├── local/
│   │   │   │   │   └── {feature}_data_source.dart
│   │   │   │   └── remote/
│   │   │   │       └── {feature}_data_source.dart
│   │   │   ├── data_models/
│   │   │   │   └── {name}_model.dart           # @freezed + fromJson
│   │   │   └── repositories/
│   │   │       └── {feature}_repository_impl.dart
│   │   ├── domain/
│   │   │   ├── domain_models/

│   │   │   ├── usecases/

│   │   └── presentation/

│   │       ├── pages/
│   │       │   └── {feature}_page.dart
│   │       ├── organism/
│   │       │   └── {name}_organism.dart        # Composed widgets for the feature
│   │       └── templates/
│   │           ├── {name}_template_mobile.dart
│   │           └── {name}_template_web.dart    # If multi-platform applies
│   │
│   └── {feature_b}/
│       ├── data/
│       ├── domain/

│
├── test/
└── pubspec.yaml
```

## Melos — Base Configuration (7.x)

In Melos 7.x, there is no `melos.yaml`. All configuration lives in the root `pubspec.yaml`.

```yaml
# pubspec.yaml (workspace root)
name: project_name
publish_to: none

environment:
  sdk: ">=3.8.0 <4.0.0"

# List all packages explicitly — globs not yet supported
workspace:
  - apps/app_name
  - packages/core
  - packages/ui_system
  - packages/feature_a
  - packages/feature_b

dev_dependencies:
  melos: ^7.5.1

melos:
  scripts:
    analyze:
      run: melos exec -- "flutter analyze --no-pub"
      description: Run flutter analyze on all packages
      packageFilters:
        flutter: true

    test:
      run: melos exec -- "flutter test --coverage"
      description: Run tests on all packages
      packageFilters:
        flutter: true
        dirExists: test

    build_runner:
      run: melos exec -- "dart run build_runner build --delete-conflicting-outputs"
      description: Run build_runner on all packages
      packageFilters:
        dependsOn: build_runner

    clean:
      run: melos exec -- "flutter clean"
      description: Clean all packages
      packageFilters:
        flutter: true
```

Each package must declare `resolution: workspace` in its own `pubspec.yaml`:

```yaml
# packages/feature_a/pubspec.yaml
name: feature_a
resolution: workspace   # ← required
dependencies:
  core: any             # ← workspace resolves local packages
```

## Folder Naming Table

| Layer | Folder | Contents | File example |
|---|---|---|---|
| **Domain** | `domain_models/` | Domain models (`@freezed`, no JSON) | `product.dart` |
| **Domain** | `usecases/` | Use cases (`@injectable`) | `get_product_usecase.dart` |
| **Domain** | `repositories/` | Repository interfaces | `product_repository.dart` |
| **Data** | `data_models/` | Data models (`@freezed` + `fromJson`) | `product_model.dart` |
| **Data** | `data_sources/remote/` | Remote sources (HTTP) | `product_data_source.dart` |
| **Data** | `data_sources/local/` | Local sources (cache, DB) | `product_data_source.dart` |
| **Data** | `repositories/` | Repository implementations | `product_repository_impl.dart` |
| **Presentation** | `ui_models/` | UIModels for the UI | `product_uimodel.dart` |
| **Presentation** | `bloc/` | BLoC + Event + State (`@freezed`) | `product_bloc.dart` |
| **Presentation** | `pages/` | Pages (route entry point) | `product_page.dart` |
| **Presentation** | `organism/` | Composed widgets for the feature | `product_card_organism.dart` |
| **Presentation** | `templates/` | Mobile/web layouts per feature | `product_template_mobile.dart` |

## Strategy Selection Guide

| Criteria | Single Project | Monorepo with Melos |
|---|---|---|
| Number of apps | 1 | 2+ |
| Shared design system | Not needed | Required |
| Team size | Small (1–5 devs) | Medium–Large (5+ devs) |
| Shared business logic | Minimal | Significant |
| CI/CD complexity | Low | Higher (per-package pipelines) |
| Onboarding cost | Low | Medium |
